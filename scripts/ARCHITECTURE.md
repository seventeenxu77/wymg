# 游戏脚本结构

`main.gd` 是场景入口和协调器，只负责生命周期、输入分发、固定帧更新以及系统调度。

逻辑层位于 `systems/`，按依赖方向排列：

1. `game_state_base.gd`：共享配置、运行状态和系统接口基底。
2. `room_system.gd`：房间生成、家具耐久度、基础实体与查询。
3. `audio_system.gd`：噪音事件、音效资源和脚步播放。
4. `round_system.gd`：四局流程、结算、商店、仓库和 GM 命令。
5. `actor_system.gd`：连续移动、碰撞、家具撞击、攻击和撤离。
6. `tool_system.gd`：道具拾取、使用、装置及状态效果。

高耦合逻辑通过 `GameStateBase` 共享同一份状态，各系统不复制运行数据。

显示层位于 `presentation/`：

- `game_hud.gd`：所有 2D HUD、分屏面板、地图、商店、结算和 GM 控制台。
- `minimap_renderer.gd`：小地图页面的纯绘制模块；通过 `GameHud` 提供的只读状态和绘图接口工作。
- `world_25d.gd`：3D 房间、角色、家具、摄像机和角色移动小跳。

显示层只读取逻辑状态并回写点击区域，不负责修改玩法流程。

状态构造位于 `state/`：

- `gameplay_state_factory.gd`：角色、状态效果、携带道具和场景装置的统一构造入口。

现有系统仍使用 `Dictionary` 作为运行时状态。新增状态字段必须先加入工厂并补充
`tests/gameplay_state_factory.gd`，不要再在各系统中复制默认字典。后续可以逐类把工厂输出替换为
类型化 `Resource`，同时在迁移期间保留旧字段兼容层。

`tool_system.gd` 当前包含两类职责：玩家道具栏操作，以及已部署装置的生命周期。继续拆分时应保持
`_selected_tool`、`_consume_selected_tool`、`_spawn_device` 和 `_find_device_entry` 这四个边界稳定，
先将机器人巡逻及装置更新迁入独立系统，再迁移输入分发，避免显示层或回合系统直接修改装置状态。

模式与网络框架：

- `modes/game_mode_catalog.gd`：集中声明经典本地双人、联机狩猎、单人冒险和回合战棋入口。
- `modes/mode_router.gd`：在主菜单和独立模式之间路由；不会修改经典本地双人的输入规则。
- `network/network_lobby.gd`：纯 Control 联机大厅，不依赖现有双分屏 HUD。
- `network/network_session.gd`：ENet 创建/加入、四个玩家槽、准备状态和开始比赛协议；玩家
  快照携带类型化职业 ID 与三格初始背包。服务器校验职业所属阵营并在准备后锁定；普通大厅
  当前固定为一件肾上腺素，其他道具等待商店与持有物校验。
- `professions/profession_definition.gd`：职业静态数据资源；当前保存稳定 ID、名称、所属阵营
  和描述，后续技能与数值引用职业 ID，不把职业配置复制进玩家运行时字典。
- `professions/profession_catalog.gd`：集中声明收藏家、侦察者、支援者和搬运者，提供槽位默认
  职业、阵营合法性与大厅显示名称。收藏家只允许怪物槽，三个盗贼职业只允许盗贼槽。
- `network/network_mansion_state.gd`：服务器权威的 36 房间宅邸、一怪物三盗贼、阶段计时、
  多人碰撞移动、家具交互、藏品放置、家具损毁、物品归属、个人携带和独立撤离；房间数据
  由现有 `RoomSystem` 按服务器种子生成。它还分别维护三个盗贼的潜行／暴露时间和短期噪音
  事件，以及怪物攻击冷却、盗贼生命、受击硬直、倒地和持续救援进度。攻击命中与救援完成均
  由服务器裁定。九种联机道具的装备、消耗、速度效果、装置生命周期、探测与警报、传送蓄力
  和中断、拳套击退，以及巡夜偶巡逻／警戒／停机／换位也位于该状态中；撤离和倒地不会直接
  决定比赛胜负。
- `network/network_tool_catalog.gd`：声明当前已迁移的联机道具类型、稳定数值索引和调试
  槽位装备。它复用本地 `TOOL_DEFS` 与统一状态工厂，不在网络层复制名称、图标或价格数据。
- `network/network_match.gd`：独立单视角联机对局；客户端发送视角换算后的输入，服务器以
  20 Hz 广播紧凑角色快照，客户端对同房间内的远端位置进行插值。低频家具变化使用可靠事件
  单独广播，不把完整 36 房间状态塞进高频移动快照；人物位置、动作、携带摘要、生命、硬直、
  攻击、救援、增益、捕兽和传送状态使用每名角色 30 个浮点值的定长 `PackedFloat32Array`；
  装备栏使用稳定道具索引和五值道具记录，活动装置使用 16 值紧凑记录。全部九种测试装备与
  三个活动装置并存时完整快照约 1108 字节，仍低于 ENet 单包安全尺寸。家具、物品与匿名噪音
  使用可靠事件，攻击命中、复起、道具使用和
  装置触发使用可靠事件；客户端只上传移动方向、交互请求、救援状态和道具操作。
  服务端只向当时处于感知范围内的敌对客户端发送噪音，事件本身也不包含制造者名字
  或玩家 ID。进入对局时先显示独立加载页，每个客户端完成宅邸构建、角色同步和渲染帧预热后
  向服务器上报资源就绪；只有当前玩家快照中的全部非观战玩家就绪，服务器才广播统一开场并
  开始阶段计时。怪物端不会把盗贼纸片放进实体渲染层，而是从权威移动快照采样短时红色残影；
  噪音同时在本机角色中心按屏幕左／右绘制扩散弧，小地图波纹只保留为辅助信息。
- `network/network_launch_options.gd`：解析多实例调试命令行；`-CombatTest` 与 `-ToolTest`
  对应的开发参数会让服务器跳过藏宝并使用同房近距离出生点，后者还会分配固定测试装备；
  两者均不进入正式玩法规则。

经典模式继续由 `main.gd` 直接运行。联机模式使用独立大厅，后续继续在新的网络比赛场景中实现
物品、技能和玩法规则，不在经典模式中增加网络条件分支。`NetworkSession` 持有连接
和大厅状态，`NetworkMatch` 只在比赛期间读取同一会话；离开比赛时由模式路由统一关闭连接。

`state/mansion_collision.gd` 是经典 `ActorSystem` 和 `NetworkMansionState` 共用的墙体、门洞、
家具占地及角色半径计算。修改宅邸碰撞时必须同时运行本地 2.5D 与联机宅邸测试，不能在网络层
复制另一套尺寸常量。`World25D.sync_network` 复用原房间、家具和角色资源，并为额外两名盗贼
创建纸片角色节点。经典模式与教程仍创建怪物、盗贼两个视口；联机模式在加载页显示后才按本机
阵营创建一个视口、一个摄像机以及对应阵营的高墙和幽灵远景节点。地板 ShaderMaterial 按纹理
路径缓存，常用 StandardMaterial 与动态纹理按渲染器复用；墙体共享基础材质，并通过 instance
uniform 保存各房间的光源位置和淡入值，不能再恢复为逐房间／逐墙复制材质。

独立教程位于 `tutorial/`：

- `tutorial_system.gd`：管理玩家 A/B 各自隔离的五房间教学、AI、目标状态、教学商店和资源清理。
- `tutorial_step_catalog.gd`：教学步骤顺序和不依赖运行状态的标题文案。
- `tutorial_hud.gd`：绘制双窗口角色选择、闪烁步骤提示、角色脚下的按键状态动画、教学面板和每侧独立退出入口。

每位玩家的教程各自创建一个隔离的 `World3D + World25D`，并按左侧键区/右侧键区定向分发输入；任一侧打开面板、进入商店或完成教程都不会锁住另一侧。教程不会读写正式比赛的房间、金币、仓库、装备或回合状态。双方都选择“退出教学并准备”后进入共享确认状态：“冲”先清理教程并等待两个渲染帧释放其 SubViewport，再创建新的正式比赛；“先等等”清理教程并返回主菜单。`tutorial_hud.gd` 会在教程关闭时额外重绘一次空画布，避免最后一帧教学弹窗残留在正式游戏上。
